## Cashier login intermittently refused (found during G0, fixed in the running layer)
Symptom: about 40% of key logins as "cashier" ended "Permission denied (publickey)" (2 of 5 throttled, 2 of 3 unthrottled, 3 of 3 just after boot); admin logins never failed.
sshd log: every successful cashier login logs "Accepted key ... found at C:/ProgramData/ssh/cashier_authorized_keys:1"; every failed one logs only "Failed publickey" with no key-file line, so on those connections OpenSSH 7.7 for Windows did not apply "Match User cashier -> AuthorizedKeysFile". Key file content, owner and ACL were correct throughout.
Finding G0-F3: a Match User key-file rule is unreliable for a standard user on this sshd build. Fix (guest/fix-cashier-key.ps1): cashier's key moved to C:\Users\cashier\.ssh\authorized_keys (owner cashier; cashier, SYSTEM, Administrators full), Match block removed; setup-ssh.ps1 updated to the same design.
After the fix: cashier 30 of 30 logins, admin 10 of 10; password and keyboard-interactive still refused for both (Permission denied (publickey)).
The snapshot clean-ssh still holds the OLD (Match) design; the fix exists only in the running layer.
